# 0027: Permanent bootstrap completion

Status: Accepted

Accepted and recorded: 2026-11-16

## Decision

Persist a durable bootstrap-completed marker in the global control-plane database. Commit it atomically with the first administrator account and administrator claim under the approved bootstrap transaction/application lock.

After successful completion, bootstrap remains disabled even if the administrator is later deleted or locked out. Do not cascade-delete, reset, or clear the marker as part of account operations. Recovery requires a separately authorized workflow; this decision does not define or enable that workflow.

The creation guard must check the permanent marker as well as existing administrator status while holding the lock. Do not rely on absence of account/claim rows as evidence that bootstrap has never occurred. A failed transaction must leave no committed completion marker, account, or claim from that attempt.

## Scope and implementation boundary

The owner approved adding a small global database record and migration to represent this rule. Exact table/schema, key, fields, constraints, ownership, mapping, migration shape, database permissions, and concrete code implementation still require an explained implementation plan before significant changes. No record or migration is generated by this documentation task.

The marker is operational history, not an authorization credential or MFA state. It grants no platform or tenant access. This decision does not define hard-deletion policy for administrator accounts or approve a command that clears bootstrap completion.

## Required later verification

Real SQL Server tests must verify atomic account/claim/marker creation, complete rollback on failure, concurrent creation producing one completion, rerun preserving credentials, and refusal after account deletion or lockout. Recovery/reset must not be silently added to make tests pass.
