# 0037: Platform password verification and restricted MFA entry

Status: Accepted, 2026-11-18.

The owner approved the [password-entry design](../architecture/platform-password-entry-proposal.md), including five consecutive failed password attempts causing a 15-minute password lockout. This is separate from the approved MFA fixed-window attempt budget and does not establish an organization-user password policy.

Use the existing Identity AccessFailedCount, LockoutEnabled, and LockoutEnd fields. Eligible platform administrators have lockout enabled when this path applies attempt state, including bootstrap-created rows with the inherited false default. Five failures persist a lockout and revoke outstanding account MFA challenges. Active lockout dates are respected even when a legacy flag is false; that flag is enabled and challenges revoked without clearing/extending the date. Requests during an enabled active lockout change no counters or dates. After expiry a new failure starts at one; correct password verification clears only the password counter/date, never MFA control state.

Identity Infrastructure owns PlatformSignInPassword, IPlatformPasswordEntry, the policy constants, and the non-record PlatformPasswordEntryResult. Normalize email using AccountEmail; query only Platform scope with the server-managed administrator claim. Organization accounts with matching emails or even a matching claim cannot supply platform credentials or receive this flow's failure updates. Unknown/nonadministrator accounts use the same empty rejection result as wrong passwords or lockout.

Normalize password input to NFC, preserving whitespace and case, rejecting missing/invalid Unicode and normalized values exceeding the existing 128-code-point maximum. Do not reapply creation minimums or the current blocklist when verifying an existing credential. Use the existing approved framework PasswordHasher settings. Unknown/noneligible input performs real dummy hash work with a process-local random dummy hash, never a persisted/default account or authentication path. This mitigates simple hash-work differences without claiming identical timing or replacing later request throttling.

Verify the credential snapshot before acquiring the account update lock. Recheck normalized email, scope/claim, exact password hash/security stamp, lockout, and MFA data under the lock. Discard stale verification without charging the changed account. Honor Identity rehash-needed outcomes atomically: update the hash/stamps and revoke prior challenges, issuing the replacement challenge against the persisted new security stamp. Correct password state may commit even when MFA is blocked/inconsistent, but MFA state is never repaired/reset/adopted and no challenge is returned then.

The ControlPlane implementation owns a fresh private context/transaction per attempt, avoiding issuer SaveChanges flushing caller-tracked data. Disable inherited logger/simple-logging/sensitive-data sinks on that private context and sanitize SQL/update exceptions without supplied values/inner exceptions. Use existing fields and packages; no schema, bootstrap grant, or blanket account update is added. TryIssueAsync was added to the existing issuer for normal nullable denial; existing IssueAsync behavior is preserved.

Password success produces only a ten-minute Enrollment or Verification challenge. Enrollment requires no confirmed credential/recovery rows and MFA disabled. Verification requires MFA enabled with confirmed credential and issued recovery data; consumed recovery rows still count as issued, so exhausted backups do not disable TOTP. The result exposes only issuance status, purpose, and opaque ticket/expiry; no email, account ID, credential, JWT, principal, cookie, refresh token, or tenant reference is returned. No public endpoint or DI registration is enabled in this slice.

See [implementation, test evidence, and limits](../development/platform-password-entry.md). Framework verification/rehash behavior is from the [pinned PasswordHasher source](https://github.com/dotnet/aspnetcore/blob/v10.0.9/src/Identity/Extensions.Core/src/PasswordHasher.cs); lockout values are owner-selected application policy.
