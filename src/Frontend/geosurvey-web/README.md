# GeoSurvey web

Angular 21 standalone frontend for the approved Phase 1 identity, organization provisioning, activation, and verified workspace flows. It uses Angular forms, services/RxJS, and ordinary responsive CSS. There is no UI component library or fabricated survey data.

## Build and checks

From this directory, with Node 24 and npm installed:

```powershell
npm ci
npm run build
npm test -- --watch=false
npm run test:totp
npm run test:e2e:typecheck
npm run format:check
```

Production assets are in `dist/geosurvey-web/browser`. The HTTPS demo host must serve that directory with an SPA fallback and proxy `/api` to the API on the same browser origin. Critical CSS inlining is disabled so styles load through a normal stylesheet link without an inline `onload` handler blocked by the host's script Content Security Policy. API URLs are relative `/api/v1`; no client connection strings or environment secrets are required. Follow the repository's Phase 1 Docker runbook for the integrated application. `npm start` serves the UI shell for frontend editing; plain HTTP Angular development hosting does not provide the required Secure refresh-cookie/API setup.

## Routes and session behavior

| Route                               | Purpose                                                                                               |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `/platform/sign-in`                 | Platform password entry                                                                               |
| `/platform/mfa`                     | Manual authenticator enrollment, one-time recovery-code delivery, authenticator/recovery verification |
| `/platform/organizations`           | Real paginated organization registry and creation                                                     |
| `/platform/organizations/:publicId` | Provisioning status, retry, one-time invitation handoff                                               |
| `/activate#TOKEN`                   | Initial administrator password setup                                                                  |
| `/sign-in`                          | Organization code, email, and password sign-in                                                        |
| `/workspace`                        | Server-verified organization marker, schema version, and administrator access                         |

`AuthService` keeps the access token and MFA challenge in memory. The backend owns HttpOnly/Secure/SameSite refresh cookies. Every unsafe auth/activation operation obtains a CSRF request token and sends `X-CSRF-TOKEN` without bearer authorization. Resource requests receive bearer authorization through the interceptor. Refresh is single-flight within a tab and uses the Web Locks API across tabs. Browsers without Web Locks require fresh sign-in rather than attempting unsafe concurrent cookie rotation. BroadcastChannel sends only session public IDs and scope to invalidate other tabs; refresh/logout also send the expected session public ID to prevent a stale view adopting or revoking a replacement session.

Authenticator material, recovery codes, and issued invitation links are transient. The activation page removes the URL fragment before its first request and sends its token only in the POST body. Reopen the original private link if this page is refreshed before completion. A refreshed MFA page returns to password entry. No credentials are saved in localStorage/sessionStorage, logged, or included in route query strings.

## Real browser acceptance

The Playwright test creates two organizations in a disposable local HTTPS demo, activates both recipients, and checks actual workspace identities and independent same-email passwords. It also proves MFA enrollment, fresh authenticator/recovery sign-in, consumed recovery rejection, secure cookie attributes, and cross-tab refresh/session handling. It never substitutes mocked API responses.

```powershell
npx playwright install chromium
$env:GEOSURVEY_ACCEPTANCE_CREDENTIALS = 'C:\private-demo\acceptance-credentials.json'
npm run test:e2e
```

The private JSON file is generated by the demo's synthetic acceptance seeder and contains `email`, `password`, and `baseUrl`. It must point to a loopback HTTPS origin. For full acceptance, use a fresh, MFA-unenrolled Platform Administrator. After successful enrollment, the runner adds only `totpSecret` to that same private fixture so a diagnostic rerun can resume. Recovery codes are never written to disk. A resumed run explicitly records fresh-enrollment/recovery checks as skipped; recreate the disposable fixture to prove the complete flow. Do not place credentials in this README, command arguments, or a tracked file.

Only sanitized counts, stage names, and the safe summary `test-results/phase-1-browser-summary.json` are retained. Tracing, video, screenshots, page snapshots, attachments, and raw error output are disabled/suppressed for secret-bearing flows. Do not enable `DEBUG=pw:api` or switch to a reporter that emits typed values. `npm run test:e2e -- --list` discovers the test without executing it.

Playwright `1.65.1` is a development-only dependency, verified against the [official npm registry](https://registry.npmjs.org/@playwright/test/latest). `@types/node` `24.19.2` supplies compile-time types for the test runner's Node 24 crypto/file APIs; it is absent from the shipped browser code. The RFC 6238 helper is test-only, checked against independent published vectors, and supplies codes to the real backend.

The frontend handover and current verification evidence are in [frontend-flow.md](../../../docs/submission/phase-1/frontend-flow.md). API DTOs follow the [shared integration contracts](../../../docs/architecture/phase-1-integration-contracts.md).
